Read the testing guide ↗
hello.test.tsVitest
import { fileURLToPath } from 'node:url';
import { expect, test } from 'vitest';
import { createShellyRuntime }
  from 'shelly-forge/testing';

test('the starter saves its counter', async () => {
  const runtime = createShellyRuntime();
  const script = fileURLToPath(
    new URL('./hello.ts', import.meta.url)
  );
  await runtime.loadScript(script, {
    env: { SHELLY_PUBLIC_GREETING: '' }
  });

  runtime.advance(60000);

  expect(runtime.kvs.get('example.hello.count'))
    .toBe('1');
});
↳ The generated starter's first timer, without the wait.

Local tests do not reproduce device memory, CPU, or every firmware behavior. The emulator runs trusted code in Node vm, not a security boundary. Verify on your intended hardware too.

03 / With your approval

Checked code.
Confirmed target.

Shelly's interpreter is not Node.js. Forge checks for unsupported APIs and device limits, then verifies startup after upload.

  1. 01 / Write

    TypeScript

    Device-specific types and bundled local imports.

    src/lighting/hallway.ts
  2. 02 / Check

    ES5 artifact

    Type checks, runtime rules, and a 65535-byte size limit.

    check lighting/hallway
  3. 03 / Deploy

    One selected script

    Upload, configure, and start on the device you approved.

    deploy lighting/hallway
  4. 04 / Verify

    Startup status

    A health window checks for errors. Failed verification attempts rollback when a different last-good artifact exists.

    status lighting/hallway

Deployment replaces the selected on-device script. Keep verification enabled.
